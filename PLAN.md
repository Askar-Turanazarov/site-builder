# Конструктор сайтов — вторая итерация: визуальный редактор, стили, шаблоны сайтов, i18n админки

## Контекст

Первая итерация дала работающую CMS: блочная модель контента, редактор с тремя языками, новости/рубрики, словарь UI-строк публичного сайта, экспорт в статику, 13 шаблонов отдельных страниц, 5 визуальных тем. После просмотра результата пользователь указал на шесть недоработок:

1. **Редактирование блоков идёт списком в сайдбаре, а не на самом превью.** Нужен холст как в Gutenberg (WordPress): перетаскивание блоков прямо на превью, панель действий на блоке, вставка «+» между блоками. Плюс отдельная страница предпросмотра сайта.
2. **Нет управления стилями из интерфейса.** Администратор без знания CSS должен менять фон, цвета текста и акцента, размер заголовка, отступы, ширину, скругления, выравнивание для каждого блока.
3. **Шаблоны есть только на уровне отдельных страниц.** Нужны готовые сайты целиком (страницы + рубрики + статьи + меню + тема + настройки), с быстрым просмотром и применением. Согласовано: **12 шаблонов** разных профилей, с продуманными мок-данными ташкентского бизнеса на трёх языках.
4. **Интерфейс самого конструктора только на русском.** Нужны RU/UZ/EN для админки (сейчас механизма нет вообще: ни куки, ни контекста, ни словаря — `src/lib/i18n.ts` обслуживает только публичный сайт).
5. **Круглый значок «N» на страницах** — это индикатор Next.js Dev Tools, отключается конфигом.
6. **`README.md` — дефолтный от `create-next-app`.** `create-next-app` — официальный генератор Next.js (каркас: package.json, tsconfig, конфиги Tailwind/PostCSS, пустой layout), но его README и неиспользуемые SVG остались в проекте. Нужен настоящий README и удаление мусора стартера.

Согласованные решения пользователя по этой итерации:
- Стили: **готовые пресеты + свободный выбор цвета (hex) и размеров**, без поля сырого CSS.
- **Отдельный экран «Дизайн сайта»**: пара шрифтов, глобальные цвета, радиусы — поверх выбранной темы, действуют и на экспорт.
- **12 шаблонов сайтов** целиком: кафе, корпоративный, агентство, магазин, блог, медцентр, образование, строительство + юруслуги, салон красоты, фитнес, туризм. Мок-данные — как будто бизнес реально работает в Ташкенте (районы, улицы, +998, суммы в сумах).
- Редактор: **драг-н-дроп на превью + панель полей справа** (без inline-редактирования текста прямо на холсте).

## Ключевые факты о текущем коде (проверено)

- `renderBlock(block, ctx)` передаёт компоненту только `{data, ctx}`; `BlockList` оборачивает блок во `Fragment` — **обёртки вокруг блока нет, `block.id` в компонент не попадает**. Это единственная точка, куда нужно добавить обёртку, чтобы не править 28 файлов блоков (14 компонентов + 14 генераторов статики).
- Живой сайт и экспорт держат идентичную вёрстку за счёт общих строк классов `CX` из `src/blocks/classes.ts` — любая правка в этом файле автоматически действует на обе ветки.
- Все цвета/радиусы блоков уже читаются из 10 переменных `--tpl-*` (`src/blocks/palette.ts`), поэтому переопределение этих переменных на обёртке блока меняет вид всего его содержимого без правки самих блоков.
- `parseBlocks` возвращает `[]`, если валидация всего массива провалилась → новое поле `style` обязано быть `.optional()`, иначе уже сохранённые страницы перестанут открываться.
- Админ-локали нет нигде: ни куки, ни провайдера, ни `useContext` во всём проекте.
- `src/app/admin/(dashboard)/block-preview/page.tsx` — временная страница проверки блоков, в сайдбаре не значится, в комментарии помечена как удаляемая. Её ~52 русские строки — демо-контент, а не UI.

### B. Пер-блочные стили (ядро)

Механизм выбран так, чтобы не править 28 файлов блоков и не зависеть от произвольных Tailwind-значений:

- **Цвета и скругления** — переопределением существующих `--tpl-*` переменных инлайн-стилем на обёртке блока. Всё содержимое блока уже читает эти переменные (`text-[var(--tpl-ink)]`, `bg-[var(--tpl-accent)]`, `rounded-[var(--tpl-radius)]`), поэтому смена акцента одним полем меняет кнопки, иконки и бейджи внутри блока. Для произвольного hex-акцента `--tpl-on-accent` считается автоматически по яркости (белый или почти чёрный), чтобы текст на кнопке остался читаемым.
- **Отступы, ширина контента, размер заголовка** — правилами в новом `src/styles/blocks.css` по `data-blk-*` атрибутам обёртки (`[data-blk-py="lg"] > * { padding-block: 6rem }` и т.п.). Файл подключается из `globals.css`, то есть попадает и в сборку Next, и в CSS экспорта. Правила лежат **вне `@layer`**, поэтому гарантированно перебивают утилиты Tailwind (`py-16 md:py-24`) — этот механизм каскадных слоёв уже проверен в проекте: неслоёное `body { background }` перебивало класс `bg-[var(--tpl-paper)]`.
- Для надёжного попадания в контейнер добавить в `CX.container`/`CX.containerNarrow` служебный класс-хук `sb-container` (одна правка в `classes.ts`, автоматически действует и на живой сайт, и на экспорт). Селектор ширины целится в `.sb-container`, а не в `> * > div` — иначе full-bleed фон Hero (img и оверлей — тоже прямые дети `<section>`) поймал бы `max-width`.
- Новый `src/blocks/style.ts`: `blockStyleSchema` (zod, все поля с дефолтами), тип `BlockStyle`, `blockStyleVars(style): React.CSSProperties` (живой рендер), `blockStyleAttrsHtml(style): string` (экспорт), `blockStyleDataAttrs(style)`. Настройки: фон, цвет текста, акцент, размер заголовка, вертикальные отступы, ширина контента, скругление, выравнивание, «скрыть блок».
- `src/blocks/types.ts`: в `Block` добавить `style?: BlockStyle`, в каждый вариант `blockSchema` — `style: blockStyleSchema.optional()`. Обязательно `.optional()`: `parseBlocks` возвращает пустой массив при провале валидации, иначе уже сохранённые страницы перестали бы открываться.
- `src/blocks/registry.tsx`: обёртка добавляется **централизованно** в `renderBlock` и в `blockListToHtml` — одинаковые атрибуты и переменные в обеих ветках, поэтому вёрстка живого сайта и экспорта остаётся идентичной; `style.hidden` пропускает блок в обеих ветках.
- Редактор: `useBlockEditor` получает `updateBlockStyle(blockId, patch)` (пишет во все три локали — стиль не зависит от языка), правая панель — вкладки «Содержимое» / «Стиль», новый `StyleEditForm` со свотчами палитры, полем hex и селектами размеров.

### C. Холст-редактор (Gutenberg-like)
- `LivePreview` превращается в `EditorCanvas`: те же блоки через `renderBlock`, но каждый обёрнут в клиентский `CanvasBlock` — рамка при наведении, плавающая панель (перетащить, вверх, вниз, дублировать, удалить), клик = выбор блока.
- **Нейтрализация интерактива внутри блока:** содержимое блока рендерится в контейнере с `pointer-events-none`, а панель действий — с `pointer-events-auto`. Это разом отключает переходы по ссылкам и отправку форм внутри превью и отдаёт клик обёртке для выбора блока (не нужно вешать `preventDefault` на каждый элемент).
- Перетаскивание — dnd-kit `DndContext` + `SortableContext` поверх холста, `useSortable({ id: block.id })` на каждой обёртке, ручка перетаскивания в панели действий; вызывает тот же `editor.reorderBlocks`, что и сайдбар.
- Зоны «+» между блоками: узкая полоса по наведению с кнопкой, открывает `AddBlockMenu` и вставляет на конкретную позицию через уже существующий `addBlock(type, atIndex)`.
- `BlockListSidebar` остаётся как структурная схема документа и делается сворачиваемым (260px ↔ узкая полоса), чтобы холст получил больше ширины.

### D. Отдельный предпросмотр
- `/admin/preview/[type]/[id]` (`type` = `page` | `post`) — рендер с настоящими `Header`/`Footer` и реальным `RenderContext`, включая черновики; сверху панель: переключение RU/UZ/EN и возврат в редактор.
- Кнопка «Предпросмотр» в `PageEditor`/`PostEditor` открывает его в новой вкладке.

### E. Экран «Дизайн сайта» + расширение тем
- Prisma: `SiteSettings` += `fontDisplay`, `fontBody`, `accentColor`, `paperColor`, `inkColor`, `radius` (все — необязательные переопределения поверх темы) + миграция.
- `palette.ts`: `themeStyleVars(themeKey, overrides)` / `themeStyleCss(themeKey, overrides)`; курируемый список шрифтовых пар с поддержкой кириллицы; расширение `THEME_PRESETS` до 12 палитр (по одной на профиль шаблона).
- Подключение выбранных шрифтов рантаймом: `<link>` на Google Fonts в публичном layout и в `shell.ts` экспорта (next/font работает только на этапе сборки).
- Новый раздел админки `/admin/design`: выбор темы карточками-свотчами, пара шрифтов, цвета, радиус, мини-превью.

### F. i18n интерфейса админки (RU/UZ/EN)
- `src/lib/admin-i18n/`: `ru.ts` (эталонный словарь, задаёт тип `AdminDict`), `uz.ts` / `en.ts` типизированы как `AdminDict` — пропущенный ключ ломает сборку, поэтому расхождение словарей невозможно. `index.ts`: тип `AdminLocale`, `isAdminLocale()`, `adminT(dict)`, серверный `getAdminLocale()` (кука `sb_admin_locale`, `cookies()` в Next 16 асинхронный — как в существующем `lib/auth.ts`), `getAdminT()` и server action `setAdminLocaleAction`.
- Серверные компоненты берут `const t = await getAdminT()`. Клиентские — `useAdminT()` из `AdminI18nProvider`, который монтируется в `(dashboard)/layout.tsx` (серверном) и получает уже выбранный словарь пропом — так на клиент уезжает только активный язык, а не все три.
- Заменить ~230 строк в 42 файлах админки; локализовать `BLOCK_LABELS` и описания блоков в `AddBlockMenu` (сейчас это две отдельные русские таблицы — свести в словарь).
- Server actions сейчас бросают готовый русский текст (`Страница со слагом "x" уже существует`) — перевести на стабильные коды ошибок (`slugTaken`, `categoryNotEmpty`, …), а перевод делать на клиенте. Иначе локализовать ошибки невозможно.
- Переключатель языка — в подвале `AdminSidebar`, рядом с email и «Выйти». Порядок работ: сначала механизм + сайдбар/дашборд, затем экран за экраном (каждый шаг компилируется независимо).

### G. 12 шаблонов сайтов целиком (самый объёмный блок работ)
- `src/lib/site-templates/types.ts`: `SiteTemplate { key, label/description ×3 языка, themeKey, settings, pages[], categories[], posts[], menu[] }`.
- 12 файлов-шаблонов, каждый со своей палитрой (`THEME_PRESETS` расширяется с 5 до 12):

  | Шаблон | Профиль | Демо-бизнес (Ташкент) |
  |---|---|---|
  | `cafe` | кафе/пекарня | кафе «Зерно», Мирабадский р-н |
  | `corporate` | корпоративные услуги/консалтинг | бизнес-консалтинг, Ц-5 |
  | `agency` | агентство/портфолио | digital-студия, Юнусабад |
  | `shop` | интернет-магазин | косметика/уход, доставка по Ташкенту |
  | `blog` | личный блог/крейтор | автор о еде и городе |
  | `clinic` | медцентр/клиника | семейная клиника, Чиланзар |
  | `education` | курсы/учебный центр | IT-курсы, Мирзо-Улугбек |
  | `construction` | строительство/ремонт | ремонт квартир «под ключ» |
  | `law` | юридические услуги | юрбюро, Шайхантахур |
  | `beauty` | салон красоты | салон, Яккасарай |
  | `fitness` | фитнес-клуб | зал/групповые, Сергели |
  | `travel` | турагентство | туры по Узбекистану |

- В каждом шаблоне: 4–5 страниц (главная + профильные), 2–3 рубрики, 3–4 статьи, меню шапки/подвала, настройки сайта. Мок-данные правдоподобные и конкретные (районы и улицы Ташкента, телефоны +998, цены в сумах, часы работы), полностью на RU/UZ/EN — без машинного перевода и без «lorem».
- `/admin/templates`: галерея карточек (свотч палитры, профиль, счётчик страниц/статей), «Посмотреть» → `/admin/templates/[key]/preview` (рендер прямо из данных шаблона, без записи в БД), «Применить» → `applySiteTemplateAction` в транзакции, с выбором «заменить весь сайт» (чистит страницы/статьи/рубрики/меню, медиатеку не трогает) или «добавить к текущему».
- Существующие пер-страничные шаблоны (`src/lib/templates/`) сохраняются для добавления отдельных страниц.

## Порядок выполнения

A → B → C → D → E → F → G. Каждый этап оставляет проект в собранном рабочем состоянии, поэтому можно останавливаться между этапами. Самый долгий — G (12 шаблонов × 3 языка), он идёт последним и наполняется шаблон за шаблоном; после каждых 3–4 шаблонов имеет смысл проверять галерею и применение в браузере.

## Проверка результата

1. `npx tsc --noEmit` и `npx eslint src prisma` — чисто.
2. `npx prisma migrate dev` + `npm run db:seed` — база поднимается с нуля.
3. Браузер, админка: перетащить блок на холсте, вставить блок через «+», поменять фон/акцент/отступы блока в панели «Стиль», убедиться, что превью меняется сразу.
4. «Предпросмотр» открывает страницу с шапкой/подвалом и переключением языков, включая черновики.
5. Переключить язык админки на UZ и EN — интерфейс переведён на всех экранах.
6. `/admin/design`: сменить шрифты/акцент → публичный сайт и экспорт отражают изменения.
7. `/admin/templates`: посмотреть 2–3 шаблона, применить один, проверить главную/страницы/новости на всех трёх языках.
8. `npm run build:export-css` → экспорт ZIP → распаковать, поднять `npx serve`, проверить, что пер-блочные стили и шрифты совпадают с живым сайтом.
9. `npm run build` — прод-сборка проходит, значка «N» нет.
